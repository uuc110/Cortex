## 1. Current Schema (✅ Built)

The existing `task_mapping` table in `src/db/schema.ts` (schema version 5):

```sql
CREATE TABLE IF NOT EXISTS task_mapping (
  cortex_id   TEXT PRIMARY KEY,   -- UUID v4, generated by cortex
  bead_id     TEXT NOT NULL,      -- Hierarchical beads ID (project-random-timestamp)
  epic_bead_id TEXT,              -- Parent epic's bead ID (nullable for standalone tasks)
  project_key TEXT NOT NULL,      -- Cortex project key (e.g., "/Users/.../cortex")
  created_at  TEXT NOT NULL       -- ISO 8601 timestamp
);
```

### Existing CRUD Operations (`src/bridge/mapping-store.ts`)

| Function | SQL | Purpose |
|---|---|---|
| `createMapping(beadId, opts)` | `INSERT INTO task_mapping ...` | Create cortex_id ↔ bead_id link |
| `getMappingByBeadId(beadId)` | `SELECT ... WHERE bead_id = ?` | Lookup by beads ID |
| `getMappingByCortexId(cortexId)` | `SELECT ... WHERE cortex_id = ?` | Lookup by cortex ID |
| `getEpicMappings(epicBeadId)` | `SELECT ... WHERE epic_bead_id = ?` | All tasks in an epic |
| `getMappingsByProject(projectKey)` | `SELECT ... WHERE project_key = ?` | All tasks in a project |
| `deleteMapping(cortexId)` | `DELETE ... WHERE cortex_id = ?` | Remove single mapping |
| `deleteMappingsByEpic(epicBeadId)` | `DELETE ... WHERE epic_bead_id = ?` | Remove all epic mappings |
| `cortexIdToBeadId(cortexId)` | `SELECT bead_id ...` | Fast ID translation |
| `beadIdToCortexId(beadId)` | `SELECT cortex_id ...` | Fast reverse translation |

## 2. Extended Schema (🔜 Fork)

### task_mapping (Extended)

```sql
CREATE TABLE IF NOT EXISTS task_mapping (
  cortex_id     TEXT PRIMARY KEY,
  bead_id       TEXT NOT NULL,
  epic_bead_id  TEXT,
  project_key   TEXT NOT NULL,
  created_at    TEXT NOT NULL,
  -- New columns for sync tracking
  synced_at     TEXT,                -- Last successful sync timestamp (ISO 8601)
  sync_status   TEXT DEFAULT 'synced'
    CHECK(sync_status IN ('synced', 'pending', 'conflict', 'orphaned')),
  bead_status   TEXT,                -- Cached status from beads (denormalized)
  bead_title    TEXT,                -- Cached title from beads (denormalized)
  bead_priority INTEGER,             -- Cached priority from beads (denormalized)
  last_bead_update TEXT,             -- Last known updated_at from beads
  source        TEXT DEFAULT 'cortex'
    CHECK(source IN ('cortex', 'beads', 'migration'))
);
```

### dep_mapping

New table to track beads dependency edges with cortex-side metadata:

```sql
CREATE TABLE IF NOT EXISTS dep_mapping (
  id            TEXT PRIMARY KEY,    -- UUID v4
  from_bead_id  TEXT NOT NULL,       -- Source beads issue ID
  to_bead_id    TEXT NOT NULL,       -- Target beads issue ID
  dep_type      TEXT NOT NULL,       -- One of 18 beads dep types
  project_key   TEXT NOT NULL,
  created_at    TEXT NOT NULL,       -- When this mapping was created
  synced_at     TEXT,                -- Last verified with bd dep tree

  UNIQUE(from_bead_id, to_bead_id, dep_type)
);
```

### label_mapping

Cache of beads labels for fast cortex-side filtering:

```sql
CREATE TABLE IF NOT EXISTS label_mapping (
  bead_id       TEXT NOT NULL,
  label         TEXT NOT NULL,
  project_key   TEXT NOT NULL,
  synced_at     TEXT NOT NULL,

  PRIMARY KEY(bead_id, label)
);
```

## 3. Sync Protocol

### Design Principle

**Beads (`bd`) is the source of truth.** Cortex's `task_mapping` is a
projection — a denormalized cache that enables fast lookups and event
correlation without calling `bd` for every query.

### Sync Direction

```
┌──────────────┐          ┌──────────────┐
│   Cortex DB  │          │   Beads DB   │
│  task_mapping │◄─────────│   (bd CLI)   │
│  dep_mapping  │  sync    │  beads.db    │
│  label_mapping│  reads   │              │
│               │─────────►│              │
│               │  writes  │              │
└──────────────┘  via bd   └──────────────┘
```

### Sync Flows

#### Flow 1: Cortex Creates → Beads

```
1. MCP tool hive_create invoked
2. Bridge calls bdCreate(title, opts)
3. bd CLI creates issue in beads.db → returns BeadIssue with bead_id
4. Bridge calls createMapping(beadId, { projectKey })
   → INSERT INTO task_mapping (cortex_id=UUID, bead_id=<from bd>, ...)
5. Bridge emits event("tasks_created", ...)
6. sync_status = "synced", synced_at = NOW
```

#### Flow 2: Beads Updates → Cortex Reflects

```
1. External tool or bd CLI directly updates beads.db
2. Cortex periodic sync (or daemon event) detects change:
   a. bdShow(beadId) → get current state
   b. Compare bead.updated_at vs task_mapping.last_bead_update
   c. If different:
      UPDATE task_mapping SET
        bead_status = bead.status,
        bead_title = bead.title,
        bead_priority = bead.priority,
        last_bead_update = bead.updated_at,
        synced_at = NOW,
        sync_status = 'synced'
      WHERE bead_id = ?
3. Emit event for downstream consumers
```

#### Flow 3: Cortex Updates → Beads

```
1. MCP tool hive_update invoked with (id, { status })
2. Bridge resolves cortex_id → bead_id via mapping table
3. Bridge calls bdUpdate(beadId, { status })
4. bd CLI updates beads.db → returns updated BeadIssue
5. Bridge updates task_mapping denormalized fields:
   UPDATE task_mapping SET
     bead_status = <new status>,
     last_bead_update = <from bd>,
     synced_at = NOW,
     sync_status = 'synced'
   WHERE cortex_id = ?
6. Emit event
```

#### Flow 4: Orphan Detection

```
1. Periodic sync queries all task_mapping rows
2. For each bead_id, check bdShow(beadId)
3. If bd returns "not found":
   UPDATE task_mapping SET sync_status = 'orphaned'
   WHERE bead_id = ? AND sync_status != 'orphaned'
4. Orphaned rows are excluded from queries but preserved for audit
```

### Sync Frequency

| Trigger | Frequency | Scope |
|---|---|---|
| After mutation | Immediate | Single row affected |
| Coordinator poll | Every 30s | All `sync_status = 'pending'` rows |
| Session start | Once | Full reconciliation for project_key |
| Daemon event | Real-time | Affected row(s) only |

## 4. Conflict Resolution

### Rule: Beads Wins

When cortex and beads disagree on task state:

```
IF task_mapping.bead_status != bdShow(beadId).status THEN
  -- Beads is authoritative
  UPDATE task_mapping SET
    bead_status = bd.status,
    bead_title = bd.title,
    bead_priority = bd.priority,
    sync_status = 'synced',
    synced_at = NOW
  WHERE bead_id = ?;
END IF;
```

### Conflict Scenarios

| Scenario | Resolution | Reason |
|---|---|---|
| Both update status simultaneously | Beads wins | bd is source of truth |
| Cortex creates, bd creates same title | Link via mapping | No conflict (different IDs) |
| Beads task deleted externally | Mark orphaned | Preserve cortex history |
| Cortex mapping exists but bd init not run | Skip sync | `isBdInstalled()` gate |
| Cortex has stale cache | Overwrite from bd | bd is authoritative |
| Network/process failure mid-sync | Mark pending | Retry on next sync cycle |

### Conflict Detection Query

```sql
-- Find all rows where cortex cache is stale
SELECT tm.cortex_id, tm.bead_id, tm.bead_status, tm.last_bead_update
FROM task_mapping tm
WHERE tm.sync_status = 'synced'
  AND tm.project_key = ?
ORDER BY tm.created_at ASC;

-- After running bdShow for each row, update those that changed
```

### Never-Conflict Fields

| Field | Owned By | Notes |
|---|---|---|
| `cortex_id` | Cortex | Never changes after creation |
| `bead_id` | Beads | Never changes after creation |
| `project_key` | Cortex | Set once on creation |
| `created_at` | Cortex | Set once on creation |
| `source` | Cortex | Set once to track origin |

## 5. Index Strategy

### Required Indexes

```sql
-- Primary key already indexes cortex_id
-- CREATE UNIQUE INDEX ... ON task_mapping(cortex_id);  -- implicit

-- Fast bead_id lookups (most common query path)
CREATE UNIQUE INDEX IF NOT EXISTS idx_task_mapping_bead_id
  ON task_mapping(bead_id);

-- Epic membership queries
CREATE INDEX IF NOT EXISTS idx_task_mapping_epic
  ON task_mapping(epic_bead_id)
  WHERE epic_bead_id IS NOT NULL;

-- Project-scoped queries
CREATE INDEX IF NOT EXISTS idx_task_mapping_project
  ON task_mapping(project_key);

-- Sync status filtering (find pending/conflict/orphaned rows)
CREATE INDEX IF NOT EXISTS idx_task_mapping_sync_status
  ON task_mapping(sync_status)
  WHERE sync_status != 'synced';

-- Cached status for fast filtering without calling bd
CREATE INDEX IF NOT EXISTS idx_task_mapping_bead_status
  ON task_mapping(project_key, bead_status);

-- dep_mapping indexes
CREATE INDEX IF NOT EXISTS idx_dep_mapping_from
  ON dep_mapping(from_bead_id);

CREATE INDEX IF NOT EXISTS idx_dep_mapping_to
  ON dep_mapping(to_bead_id);

CREATE INDEX IF NOT EXISTS idx_dep_mapping_type
  ON dep_mapping(dep_type);

CREATE INDEX IF NOT EXISTS idx_dep_mapping_project
  ON dep_mapping(project_key);

-- label_mapping indexes
CREATE INDEX IF NOT EXISTS idx_label_mapping_label
  ON label_mapping(label);

CREATE INDEX IF NOT EXISTS idx_label_mapping_project
  ON label_mapping(project_key);
```

### Index Rationale

| Index | Justifies | Query Pattern |
|---|---|---|
| `idx_task_mapping_bead_id` | `beadIdToCortexId()` + `getMappingByBeadId()` | Translate beads ID → cortex ID |
| `idx_task_mapping_epic` | `getEpicMappings()` | List all tasks in an epic |
| `idx_task_mapping_project` | `getMappingsByProject()` | List all tasks in a project |
| `idx_task_mapping_sync_status` | Sync loop | Find rows that need re-sync |
| `idx_task_mapping_bead_status` | Status-filtered queries | `hive_query({ status })` without calling bd |
| `idx_dep_mapping_from` | Forward dependency lookup | "What does this task block?" |
| `idx_dep_mapping_to` | Reverse dependency lookup | "What blocks this task?" |
| `idx_dep_mapping_type` | Type-filtered dep queries | "Find all `causes` relationships" |

### Partial Indexes

The `sync_status` index uses a `WHERE` clause to only index non-synced rows.
Since ~95% of rows will be "synced" in steady state, this keeps the index
small and fast for the sync loop.

## 6. Dependency Type Mapping

### All 18 Beads Dependency Types → Swarm Concepts

| # | Beads Type | Inverse | Swarm Concept | Gates Ready? | Usage |
|---|---|---|---|---|---|
| 1 | `blocks` | `blocked-by` | Task A must complete before B starts | **Yes** | Core scheduling |
| 2 | `blocked-by` | `blocks` | Inverse perspective of blocks | **Yes** | Reverse query |
| 3 | `enables` | `enabled-by` | Soft dep — B can start without A but A helps | No | Priority hints |
| 4 | `enabled-by` | `enables` | Inverse of enables | No | Reverse query |
| 5 | `parent` | `child` | Epic → subtask hierarchy | No | Tree structure |
| 6 | `child` | `parent` | Subtask → epic hierarchy | No | Reverse tree |
| 7 | `relates-to` | `relates-to` | Informational link (symmetric) | No | Context |
| 8 | `duplicates` | `duplicated-by` | A is a duplicate of B | No | Dedup |
| 9 | `duplicated-by` | `duplicates` | B was duplicated by A | No | Dedup reverse |
| 10 | `precedes` | `follows` | Ordering hint without hard block | No | Sequencing |
| 11 | `follows` | `precedes` | Inverse of precedes | No | Sequencing |
| 12 | `causes` | `caused-by` | Root cause tracking (bug chains) | No | Debugging |
| 13 | `caused-by` | `causes` | Inverse: effect of cause | No | Debugging |
| 14 | `includes` | `included-in` | Molecule membership | No | Grouping |
| 15 | `included-in` | `includes` | Inverse molecule membership | No | Grouping |
| 16 | `requires` | `required-by` | Hard prerequisite (stricter than blocks) | **Yes** | Critical path |
| 17 | `required-by` | `requires` | Inverse of requires | **Yes** | Critical path |
| 18 | `tests` | — | Test-task relationship (unidirectional) | No | QA tracking |

### Ready-Work Computation

Beads uses a **recursive CTE** to compute which tasks are ready. The CTE
walks three dep types that gate execution:

```sql
-- Simplified version of beads' ready-work CTE
WITH RECURSIVE blocked_tasks AS (
  -- Base case: tasks that have unresolved blocking deps
  SELECT DISTINCT d.issue_id AS bead_id
  FROM dependencies d
  JOIN issues i ON d.depends_on_id = i.id
  WHERE d.type IN ('blocks', 'blocked-by', 'requires', 'required-by')
    AND i.status NOT IN ('closed')

  UNION ALL

  -- Recursive case: tasks blocked by blocked tasks
  SELECT d.issue_id
  FROM dependencies d
  JOIN blocked_tasks bt ON d.depends_on_id = bt.bead_id
  WHERE d.type IN ('blocks', 'blocked-by', 'requires', 'required-by')
)
SELECT i.*
FROM issues i
WHERE i.status = 'open'
  AND i.id NOT IN (SELECT bead_id FROM blocked_tasks);
```

### How Swarm Currently Uses Dependencies

Cortex currently uses only `blocks` type (hardcoded in several places):

| File | Code | Dep Type Used |
|---|---|---|
| `src/orchestrator/goal-handler.ts:119` | `bdDepAdd(fromId, toId, "blocks")` | blocks |
| `src/project/project-handler.ts:203` | `bdDepAdd(fromId, toId, "blocks")` | blocks |
| `src/bridge/bead-client.ts:388` | `type = "blocks"` (default param) | blocks |

### Fork Expansion Plan

The fork should use more dep types for richer task graphs:

| Swarm Operation | Current | Fork |
|---|---|---|
| Subtask depends on sibling | `blocks` | `blocks` (keep) |
| Epic contains subtask | Implicit `parent_id` | `parent` + `child` |
| Bug caused by another task | Not supported | `causes` + `caused-by` |
| Test validates a feature | Not supported | `tests` |
| Feature enables optimization | Not supported | `enables` + `enabled-by` |
| Duplicate detection | Not supported | `duplicates` + `duplicated-by` |
| Phase ordering | Implicit via wave number | `precedes` + `follows` |
| Molecule grouping | Not supported | `includes` + `included-in` |

## 7. Query Patterns

### Common Queries with the Extended Schema

#### Get all ready tasks (without calling bd)

```sql
-- Uses cached bead_status instead of calling bd ready
SELECT tm.cortex_id, tm.bead_id, tm.bead_title, tm.bead_priority
FROM task_mapping tm
WHERE tm.project_key = ?
  AND tm.bead_status = 'open'
  AND tm.sync_status = 'synced'
  AND tm.bead_id NOT IN (
    SELECT dm.from_bead_id
    FROM dep_mapping dm
    JOIN task_mapping tm2 ON dm.to_bead_id = tm2.bead_id
    WHERE dm.dep_type IN ('blocks', 'blocked-by', 'requires', 'required-by')
      AND tm2.bead_status != 'closed'
  )
ORDER BY tm.bead_priority ASC;
```

> **Note:** This is an approximation. For authoritative ready-work, always
> call `bd ready --json` which uses the full recursive CTE in beads.db.
> Use this SQL for fast UI rendering with eventual consistency.

#### Get epic task tree

```sql
SELECT tm.cortex_id, tm.bead_id, tm.bead_title, tm.bead_status, tm.bead_priority
FROM task_mapping tm
WHERE tm.epic_bead_id = ?
  AND tm.sync_status != 'orphaned'
ORDER BY tm.bead_priority ASC, tm.created_at ASC;
```

#### Find stale mappings

```sql
SELECT tm.cortex_id, tm.bead_id, tm.synced_at, tm.sync_status
FROM task_mapping tm
WHERE tm.project_key = ?
  AND (
    tm.sync_status = 'pending'
    OR tm.synced_at < datetime('now', '-5 minutes')
    OR tm.synced_at IS NULL
  )
ORDER BY tm.synced_at ASC NULLS FIRST
LIMIT 50;
```

#### Dependency graph for a task

```sql
-- All direct dependencies (both directions)
SELECT
  dm.from_bead_id,
  tm1.bead_title AS from_title,
  dm.dep_type,
  dm.to_bead_id,
  tm2.bead_title AS to_title
FROM dep_mapping dm
LEFT JOIN task_mapping tm1 ON dm.from_bead_id = tm1.bead_id
LEFT JOIN task_mapping tm2 ON dm.to_bead_id = tm2.bead_id
WHERE dm.from_bead_id = ? OR dm.to_bead_id = ?
ORDER BY dm.dep_type, dm.created_at;
```

#### Tasks with a specific label

```sql
SELECT tm.cortex_id, tm.bead_id, tm.bead_title, tm.bead_status
FROM task_mapping tm
JOIN label_mapping lm ON tm.bead_id = lm.bead_id
WHERE lm.label = ?
  AND tm.project_key = ?
  AND tm.sync_status = 'synced'
ORDER BY tm.bead_priority ASC;
```

#### Project-wide sync status summary

```sql
SELECT
  sync_status,
  COUNT(*) as count,
  MIN(synced_at) as oldest_sync,
  MAX(synced_at) as newest_sync
FROM task_mapping
WHERE project_key = ?
GROUP BY sync_status;
```

#### Dependency type distribution

```sql
SELECT
  dep_type,
  COUNT(*) as count
FROM dep_mapping
WHERE project_key = ?
GROUP BY dep_type
ORDER BY count DESC;
```
